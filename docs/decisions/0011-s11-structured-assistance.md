# Decision 0011: optional constrained assistance with immutable confirmation

Date: 2026-11-02 (Asia/Kolkata)

Keep the recorded FastAPI/Python and React stack. A provider-neutral structured JSON
protocol wraps OpenAI Responses over existing HTTPX; credentials are optional server
settings. The supported default snapshot is `gpt-5.4-mini-2026-03-17`, verified in
current official documentation. Its no-reasoning default suits bounded selections.
No provider tool execution, agent framework or JavaScript SDK is needed.

Local rules extract explicit retention/day and freshness/second phrases and produce
consequential missing questions from executable request state. Model output can
prioritize only these checked source passages/values/question keys. Broader semantic
extraction remains manual; this conservative boundary avoids unverified assumptions.
User edits and confirmation remain required before applying proposals. Preserve the
original description, proposal and versioned accepted request in tenant/project-owned
append-only records. Bind its policy/workload fingerprint to optional assessment
confirmation provenance, enforced in the API and database. Cost/budget edits do not
change accepted requirements. The deterministic manual workflow stays available.

Model-generated free text is not needed to communicate authoritative findings.
Instead, select allowed candidate/evidence/reason cards, validate exact references and
render checked text plus the existing calculated metric components. Always include
scope limitations. No competing financial value or executable instruction can enter
the UI through the provider response. Explanation generation is ephemeral and cannot
modify immutable reports. The report/decision fingerprints bind every response.

Show the precise provider summary before opt-in. Intake can send reviewed description;
explanations contain only IDs, outcome and reason codes. Exclude raw records, schemas,
query text/literals/identifiers, paths, price amounts and secrets. No automatic call
on upload, polling, benchmark or result load. Use `store: false` without claiming that
it overrides provider retention policy. Controlled failure statuses produce usable
local fallback; no provider response bodies or prompt values are logged.

Pessimistically reserve UTF-8 serialized request bytes plus output-token allowance
under a database lock before any network call. Count failures and concurrent attempts;
no automatic retries/refunds. Budget explanations per assessment and intake per project
so new proposals cannot evade admission. Limits are configurable; reservations are
not actual billing. Fixed HTTPS destination, no redirects, bounded body and timeouts.

See [AI boundary guide](../ai-boundaries.md) for settings, contracts, failure behavior,
official sources, limits and verification status. No live provider/customer claim.
