# S04 workloads and integrity

This local workflow proves supported dataset meaning and compares query outputs. It
does not benchmark latency, concurrency, freshness or savings. Local evidence is not
a server measurement or customer validation.

## Reproduce a pass and a rejection

From the repository root after locked setup:

```bash
export PATH="$PWD/.tools/node24/bin:$PWD/.tools/uv-bin:$PATH"
uv sync --locked --all-groups --project backend
uv run --locked --project backend data-optimizer integrity-check \
  examples/s04-events.ndjson examples/s04-reordered.ndjson \
  --request examples/s04-integrity-request.json --output /tmp/s04-passed.json
uv run --locked --project backend data-optimizer integrity-check \
  examples/s04-events.ndjson examples/s04-corrupted.ndjson \
  --request examples/s04-integrity-request.json --output /tmp/s04-failed.json
```

The first exits 0 with content and query checks passed. The second exits 1 and persists
failure reasons: a legitimate duplicate was replaced by a different event. Exit 1 also
covers incomplete (`not_checked`) comparisons; exit 2 means a request/input/worker error
prevented complete evidence. Require a successful exit and matching input/request
fingerprints as well as JSON status; exit 2 leaves any previous output untouched.
Input/request paths and their hard links cannot be overwritten. Sources
remain unchanged. All examples are synthetic. Cross-format fixtures are generated by
`backend/tests/fixtures/integrity.py` and tested against real DuckDB and PyArrow.

## Executable workload contract

`workload` is `workloads.models.Workload`, version 1, DSL `s04.1`. It accepts up to 32
uniquely named queries, optional concurrency and its scope: `unknown`, `single_process`
with count 1, or user-declared `production`. Production requirements may be recorded;
this runner executes serially and measures no production performance. Query frequency
per day, freshness seconds and target latency seconds are optional. Null means unknown;
zero frequency/freshness is a supplied value.

| Operation | Fields and behavior |
| --- | --- |
| `full_scan` | All columns and records; duplicates retained |
| `projection` | Nonempty `columns` |
| `filter` | Nonempty `predicates`, optional projection |
| `time_range` | Timestamp column, inclusive start, exclusive end; optional projection |
| `grouped_aggregate` | Nonempty `group_by`, allowlisted `count`, `sum`, `min`, `max`, `avg` with unique aliases |

Predicates combine with AND: `eq`, `ne`, `lt`, `le`, `gt`, `ge`, `is_null`,
`is_not_null`. Null predicates omit `value`; ordinary predicates require it. SQL null
semantics apply. `COUNT(*)` counts records; `COUNT(column)` counts nonnull values.
SUM/AVG require numeric columns. Predicates require the column's exact logical type;
the compiler never implicitly converts text identifiers or timestamp strings.

Literals use `{ "type": "decimal", "value": "2.00" }`, with every value a JSON string.
Types: string, integer, decimal, float, boolean, timestamp_aware, timestamp_naive and date.
Time endpoints must have matching awareness and form a nonempty range. Only finite
numbers and microsecond timestamps are supported. Engine date/datetime infinity sentinels
are rejected. All identifiers are ASCII, 1–64 characters, starting with a letter or
underscore; case-insensitive collisions fail. Unknown fields/columns, SQL expressions,
paths, joins, external readers and extensions are unavailable. Values are bound
parameters against a fixed in-memory relation. Paths are separate local CLI arguments.

Results are unordered multisets unless `order_by` covers every output column. This
provides a total order with NULLS FIRST and indistinguishable ties. It represents a
sorted analytical query; source row order is independently `limits.order_required`.

## Equality and evidence

Request `baseline`/`candidate` each contain S03 `ProfileOptions`: format, optional
schema overrides and CSV null tokens. These fingerprinted choices define interpretation,
not inference. Giving a lossy override to both inputs cannot prove their pre-override
meaning. Sampling is rejected: integrity always traverses the complete copies.

Canonical encoding uses typed length framing, sorted object keys and ordered arrays.
Missing keys differ from present nulls. Decimal coefficient, exponent and sign remain
exact independently of Decimal context. Float binary64 bits, including signed zero,
remain distinct. Aware timestamps compare UTC instants at microsecond resolution;
naive wall-clock timestamps have a separate type. The S03 statistics sketch is not an
integrity proof and is not used for equality.

A bounded SQLite multiset compares full canonical bytes and multiplicities. Row count,
logical field/type sets, null/missing counts and decimal scale/precision have separate
checks; canonical content detects changed values, timestamps and duplicate counts.
Both-Parquet inputs also check declared Arrow schemas. Row-order and original-byte
checks are selectable. SHA-256 identifies inputs, settings, content, workloads, results
and evidence; full multiset equality does not depend on row-hash collision assumptions.

Query tolerances default to zero. Explicit absolute/relative values are finite decimals
between 0 and 1. Only floating point outputs use
`abs(a-b) <= max(absolute, relative * max(abs(a), abs(b)))`. Other types remain exact.
Stored content remains exact even when tolerant query outputs pass. Unordered tolerant
results use bipartite matching preserving multiplicity, including overlapping tolerance
neighborhoods; over 256 rows yields not_checked. Ordered results compare positionally.
DuckDB AVG of decimals returns a float; default output comparison remains exact.

Evidence includes separate content/query statuses, requirement/workload fingerprints,
engine versions, query tolerances/order policies and a capability matrix. An empty
workload has `workload_status=not_checked`, reason `missing_workload`, while content can
pass. Supplied unsupported/over-quota workloads leave overall status `not_checked` unless
content/output already failed. Performance is always `not_measured`; equality never
establishes a latency or concurrency pass. Preserve the reviewed request alongside the
report for reproduction. `integrity.service.read_evidence` checks schema and fingerprint;
fingerprints detect corruption, not authenticity of locally authored evidence.

Reports omit raw values and source paths but include field names, schema/count/scale
summaries and hashes. Review potentially sensitive metadata before sharing.

## Capabilities and resource boundary

The matrix describes conservative source eligibility, not an implemented S05 converter.
Consumers must require supported capability plus passed candidate integrity.

| Capability | Boundary |
| --- | --- |
| Canonical comparison | Preserve nested, mixed and missing values; malformed/unsupported input fails |
| Parquet | Exclude missing, mixed, nested without explicit encoding, integers beyond int64 and decimals beyond decimal128 |
| NDJSON | Exclude binary/float/date without encoding; timestamps need reviewed override; nested Parquet needs an encoding contract |
| CSV | Rectangular nonnull text only |
| Workloads | Rectangular single types; exclude nested/mixed/missing/all-null columns, unsafe/colliding names, unsupported precision/range and engine date/time sentinels |
| Byte-changing conversion | Excluded when original bytes are required |

Retain original bytes for lexical formatting, signatures, original timezone spelling and
unmodeled annotations. Reordered object keys/equivalent timestamp offsets can pass logical
equality. A both-Parquet declared-schema change fails despite matching observed values.
Cross-format checks cover observed logical values under the reviewed contract, not identical
physical schemas or unobserved possible values.

Public `verify_files` uses a Linux subprocess: default 2 GiB address space, 60 seconds CPU
plus 2 seconds parent wall grace, no core dumps, 256 MiB SQLite file and 1,000,000 rows/input.
S03 raw/decoded/record limits also apply. DuckDB uses one thread, 128 MiB managed memory,
no spill/external access/automatic extensions, and locked configuration. Results cap at
10,000 rows/query; requests at 256 KiB and reports at 2 MiB. Limits are policy defaults,
not proven capacity. The parent removes its private temporary directory, including raw
canonical spill rows, after success/failure/worker timeout. Use private/encrypted temporary
storage. Whole-process-crash cleanup and OS isolation remain S06/S09.

This local boundary is not a production sandbox. Internal engine/runner helpers require
already bounded callers. S04 adds no UI/API or PostgreSQL evidence tables; S09 owns
tenant-scoped orchestration/storage. S06 adds benchmark isolation and actual measurements.
